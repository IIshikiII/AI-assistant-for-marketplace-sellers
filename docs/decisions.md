# Решения

Короткий журнал решений: что выбрали и почему. Новое решение — новая запись сверху.

## 2026-10-23 — Стек MVP

**Решение:** Python 3.12 + FastAPI, страницы на Jinja2 + HTMX, PostgreSQL + Alembic, DeepSeek через SDK `openai`, Docker Compose на собственном сервере за nginx.

**Почему:**
- Один язык и один контейнер: проще вайбкодить, меньше движущихся частей, нет отдельной сборки фронтенда.
- HTMX покрывает типичный интерфейс ассистента (формы, частичное обновление, потоковый ответ через SSE) без React-инфраструктуры. Если интерфейс сильно усложнится, фронт можно вынести отдельно, API на FastAPI останется.
- DeepSeek задан командой; его API совместим с OpenAI, поэтому SDK `openai` и лёгкая смена провайдера при необходимости.
- Postgres вместо SQLite: на сервере всё равно Docker, а миграции и типы данных сразу как в проде.
- Sync SQLAlchemy вместо async: проще код, для нагрузки MVP хватает.

## 2026-10-23 — Деплой

**Решение:** код едет на сервер архивом по SSH (сервер не ходит в GitHub), релизы в `/opt/seller-assistant/releases`, переключение симлинком `current` после успешного `/readyz`, иначе автооткат. Автодеплой из `main` через GitHub Actions.

**Почему:** не нужны registry и доступ сервера к GitHub; откат за секунды; одинаковый скрипт локально и в CI.
